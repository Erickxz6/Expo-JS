2. Variables

Una variable sirve para guardar un dato bajo un nombre, de modo que no haya que repetirlo cada vez que se necesite y se pueda cambiar en un solo lugar. Puede pensarse como una caja con una etiqueta: adentro guarda un valor, y la etiqueta (el nombre) dice qué representa ese valor. Un buen nombre de variable documenta el programa por sí solo: no es lo mismo leer let x = 4.2; que leer let notaFinal = 4.2;.

Así se ve

let nombre = "Ana";
const PI = 3.1416;
nombre = "Ana María";   // let sí permite cambiar el valor
PI = 3;                 // esto falla: const no se puede reasignar

Intentar reasignar una variable declarada con const produce el error Uncaught TypeError: Assignment to constant variable. Este mensaje aparece apenas el motor de JavaScript encuentra la línea que intenta cambiar el valor de una constante; por eso const solo debe usarse cuando el valor realmente no va a cambiar durante la ejecución.

3. Datos y tipos de datos

Cada valor en JavaScript tiene un tipo, y el tipo determina qué operaciones son válidas sobre él: los números se pueden sumar, los textos se pueden unir. Existen siete tipos primitivos (number, string, boolean, undefined, null, symbol y bigint) y un octavo grupo, object, que agrupa las colecciones de datos. El operador typeof permite preguntar de qué tipo es un valor en tiempo de ejecución. JavaScript tiene tipado dinámico: el tipo lo determina el valor que se guarda, no una declaración previa, así que una misma variable puede cambiar de tipo con el tiempo — aunque poder hacerlo no significa que sea buena práctica. Dos particularidades vale la pena mencionar: typeof null devuelve "object" por un error histórico del lenguaje que nunca se corrigió para no romper código antiguo, y NaN ("Not a Number") es, de forma contraintuitiva, de tipo number.

Así se ve

typeof "hola"     // "string"
typeof 42         // "number"
typeof true       // "boolean"
typeof null       // "object"  (rareza histórica)
typeof NaN        // "number"  (rareza también)

4. La operación de asignación

El signo = en programación no es una igualdad matemática, es una orden: "toma lo que hay a la derecha y guárdalo en lo que hay a la izquierda". Por eso una línea como contador = contador + 1;, que sería absurda en álgebra, es perfectamente normal en código: primero se calcula el lado derecho con el valor actual de contador, y solo después se guarda el resultado en esa misma variable. Esta diferencia es también la razón por la que = (asignar) y === (comparar) son operadores completamente distintos; confundirlos es uno de los errores más difíciles de detectar, porque el código sigue "funcionando" sin lanzar ningún error. El orden de las líneas importa: let total = precio * cantidad; solo puede ejecutarse si precio y cantidad ya tienen un valor asignado antes. Por último, existen operadores compuestos como += e ++, que son atajos de escritura muy comunes en código profesional, sobre todo dentro de ciclos.

Así se ve

let contador = 0;
contador = contador + 1;   // forma larga
contador += 1;             // forma corta, mismo resultado
contador++;                // atajo aún más corto
